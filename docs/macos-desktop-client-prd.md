# MineM macOS 客户端 PRD

> 状态：已确认并实施。包含“页面链接复制”“页面刷新”和“MineM 创作助手”。
>
> 本文记录当前已实施基线。下一版本“本地能力运行时与 AI 操作中心”的产品方案见 [MineM 本地 AI 客户端 PRD](MineM_LOCAL_AI_CLIENT_PRD.md)。

## 1. 背景

MineM 当前通过本地网页服务提供素材管理、导入、预览、故事线和 AI 演讲台。用户需要保留浏览器访问方式，同时获得可安装、可双击启动的 macOS 客户端，降低 Docker、Python 和本地地址的使用门槛。

## 2. 产品目标

1. 支持 macOS 用户安装 `MineM.app` 并双击启动。
2. 客户端与网页端使用同一套功能、界面和数据模型。
3. 客户端本机模式自动启动 MineM 服务，无需用户操作 Docker 或终端。
4. 保留浏览器访问能力，既支持本机地址，也支持未来团队部署地址。
5. 不改变现有素材生成、导入和 AI 能力的业务逻辑。
6. 让客户端能承载 MineM 内部链接，并提供清晰、受控的多标签导航体验。

## 3. 非目标

- 本期不开发 Windows 客户端。
- 本期不把用户素材上传到云端，也不改变本地数据所有权。
- 本期不替换现有 Python 后端、SQLite 或 React 前端。
- 本期不改变 Docker 的开发与部署用途。

## 4. 用户与场景

| 用户 | 场景 | 期望结果 |
| --- | --- | --- |
| 个人素材运营者 | 双击打开本地平台、导入和管理素材 | 无需先启动服务，素材仍保留在本机 |
| 汇报创作者 | 在客户端预览、创建故事线、使用 AI 演讲台 | 与网页端体验一致，预览正常可用 |
| 团队成员 | 使用浏览器或客户端访问团队服务 | 同一账号和权限下看到相同数据 |
| 开发与运维人员 | 使用 Docker 开发或部署 | 不与客户端数据目录和服务实例冲突 |

## 5. 核心流程

### 5.1 本机客户端首次启动

1. 用户从 `.dmg` 安装 `MineM.app`。
2. 用户双击应用。
3. 客户端创建专属本机数据目录。
4. 客户端立即显示轻量启动页，在后台启动本机 MineM 服务并进行健康检查。
5. 健康检查成功后，客户端进入素材库首页。
6. 后续再次打开时，保留所有本机素材、缩略图、故事线与设置。

### 5.2 浏览器访问

1. 用户通过浏览器访问本机或团队服务 URL。
2. 浏览器端调用既有 API。
3. 素材列表、导入任务、预览和详情与客户端保持一致。

### 5.3 服务异常

1. 客户端发现服务未成功启动或健康检查超时。
2. 客户端显示启动失败原因、日志位置与“重试”操作。
3. 不加载空白平台页，也不创建重复服务实例。

### 5.4 客户端内导航

1. 用户在详情页点击“打开链接”、预览页链接，或页面通过新窗口方式发起 MineM 内部跳转。
2. 客户端在顶部标签栏中新建对应标签页，不丢失当前素材库页面。
3. 新标签页支持关闭；关闭后回到原页面。
4. `127.0.0.1` 本机 MineM 地址与已配置的团队服务地址在客户端内打开。
5. 非 MineM 的外部网页仅在用户明确点击链接或页面发起显式新窗口时由 macOS 默认浏览器打开；素材 iframe 的 `src`、重定向和子文档加载继续留在 iframe 内，不能被误判为顶层外链。

### 5.5 平台升级后的客户端更新

1. 开发人员修改 React 前端、本机服务、模板、素材处理或运行依赖后，执行统一桌面构建命令。
2. 构建生成新版本 `.dmg`；用户将新版本拖入“应用程序”覆盖旧版。
3. 应用包更新只替换程序与内置服务，`Application Support/MineM` 中的用户数据不被删除。
4. 新版本启动时识别同一数据目录下的旧版客户端托管服务；先安全停止旧服务，再启动当前版本，不能同时写入同一份数据。
5. Docker、开发服务和其他非客户端托管进程不允许接管或终止，端口冲突时使用独立动态端口。
6. 仅数据库或用户素材发生变化时，不需要重新打包客户端。

## 7. 数据与安全

- 本机模式数据保存于 `~/Library/Application Support/MineM/`，不写入 `.app` 包体。
- 本机服务只监听 `127.0.0.1`，不向局域网暴露素材内容。
- 安装包不包含用户上传素材、SQLite、缩略图、导入路径或语音模型。
- 客户端不得绕过现有导入安全校验、文件白名单、SQLite 锁和素材去重规则。

## 8. 关键体验约束

- 客户端只负责启动和承载平台，不改变页面布局、预览尺寸和素材生成机制。
- 本机服务只启动一个实例；只复用当前客户端版本、当前数据目录且由客户端托管的健康实例。
- `8790` 可用时优先使用；被 Docker、开发服务或其他程序占用时自动选择新的本机端口，不接管外部实例。
- 客户端升级不能删除用户数据。
- 每个桌面版本发布前必须执行“旧版托管 Sidecar 仍运行”的覆盖升级测试；不得依赖用户手工结束进程或删除运行时清单。
- 导入与缩略图生成等耗时任务继续由后端执行，不能阻塞客户端主界面。
- 不能依赖网页端自行处理新窗口；客户端必须显式接管新窗口请求并给出导航结果。

## 9. 成功指标

- 新用户从双击应用到看到素材库首页的成功率。
- 本机客户端启动失败率与平均启动耗时。
- 客户端与浏览器端的 API 和预览一致性。
- 升级后本机数据保留成功率。

## 10. 待确认事项

1. 本期是否只支持本机模式，还是同时交付“团队服务 URL”切换。
2. 是否需要 Apple Developer 签名与公证，供非开发环境直接安装。
3. 客户端名称是否确定为 `MineM`，应用图标是否已有正式资源。已确认使用蓝底白色 `M` 的 MineM 品牌图标。
4. 本机服务采用动态端口发现，`8790` 只作为兼容优先端口。

## 11. 本期确认决策

- 本期交付本机模式，客户端自动启动本机 MineM 服务；团队服务 URL 切换保留为后续 P1 能力。
- 本机服务优先使用 `8790`；端口被占用时自动选择新的回环端口，不接管、不停止也不复用外部实例。
- 应用名称使用 `MineM`；客户端、Finder、Dock 和菜单栏统一使用蓝底白色 `M` 的 MineM 品牌图标，Apple 签名与公证在正式发布阶段补齐。

## 12. 本次变更待确认

1. 客户端新增简化标签栏：主页标签固定，内容页可多开；标签页仅提供关闭能力。

3. “打开链接”按钮在客户端中会新开内容标签，而不是静默失败。
4. 平台代码改动后的发布方式统一为 `npm run desktop:build`，然后以新 `.dmg` 覆盖安装；用户数据目录保持不动。
5. 每个可独立打开的详情或预览页面右上角新增无文字的复制图标，点击复制当前 URL；成功后仅给出短暂状态反馈。
6. 与复制图标并列新增刷新图标，点击重新加载当前页面，用于查看修改后或重新生成后的最新内容；刷新不修改数据、不重复导入。

## 12.1 MineM 创作助手

### 目标

在 MineM.app 之外提供常驻但不打扰的桌面创作助手。用户不在浮窗填写编号、链接、来源或要求，只选择一个场景并复制可填写的短模板到 Codex 或其他可执行命令的 AI 产品；在发送前把路径、链接、编号或要求贴入模板空白项，仍缺少的信息再由 AI 追问。

助手包含“汇报”“页面”“案例”三组场景，不设置资源治理模式。资源素材的检索、合并、标签和治理仍在 MineM 管理平台完成。

### 唤起与窗口行为

1. 用户可从 MineM 菜单栏图标或全局快捷键 `Option + Command + M` 唤起右侧抽屉；同时注册 `Control + Option + M` 作为 macOS 系统或前台应用抢占主快捷键时的备用键，菜单栏入口始终保留。
2. 首次完成本机初始化后自动展示一次抽屉，帮助用户理解如何与 Codex 等 AI 产品配合；关闭后不再自动打扰。
3. 创作助手首次唤起位于当前可用屏幕右侧，用户可拖动展开态顶部空白区或收起图标移动位置。展开态为 `340` 点宽的紧凑工具抽屉，收起态为 `48×48` 点的圆形 MineM 图标浮窗；原生窗口必须透明且关闭系统矩形阴影，不得显示方形白色底板、标题或文字。点击图标或再次按全局快捷键恢复展开。
4. 抽屉提供两个独立动作：收起只保留图标，关闭则完全隐藏助手。两种动作都不会停止 MineM 本机服务，也不会改变主窗口标签页。
5. 顶部不重复展示快捷键说明，只保留收起和关闭图标；主快捷键写入收起按钮与启动图标的悬浮提示，所有图标必须提供辅助功能名称。
6. 抽屉内快捷键为：`Command + 1/2/3` 切换汇报、页面、案例场景，`Esc` 关闭。复制入口属于每一条场景，不设置全局表单提交。
7. 抽屉采用扁平工具面板：单层背景、细分隔线、小圆角、无渐变、无嵌套卡片、无按键胶囊和厚重阴影。场景使用分隔列表，每行包含图标、短标题、单行说明和复制图标；点击整行或复制图标均复制同一指令。
8. 失去焦点不得自动收起或关闭。收起、关闭入口不得依赖页面业务状态，CLI 未安装时也必须可用。
9. 复制期间只锁定当前场景行，其他场景仍可浏览；原生剪贴板失败时自动降级到 WebView 剪贴板。任一链路都必须从 macOS 系统剪贴板回读到完整指令后才可显示成功；成功行短暂显示绿色勾选并提示“已复制，可粘贴到 AI 对话”，失败或超时必须立即恢复，不得卡死、误报成功或重复显示两套错误。
10. Web 平台顶部提供“创作”入口。点击后由本机服务唤起已安装客户端中的同一创作助手；客户端必须使用自身当前真实安装路径完成唤起，不得假设位于 `/Applications`。未安装客户端时明确提示安装，不生成第二套场景或指令逻辑。
11. 浮窗不得出现 `input`、`textarea`、`select`、命令预览、自定义模板、当前页面识别或草稿恢复。复制文本可以包含场景专属的空白信息项，用户在 AI 输入框中填写，不回到助手表单。
12. 每条指令固定绑定一个真实技能：汇报使用 `minem-report-workflow`，页面使用 `minem-html-page`，案例使用 `minem-case-material`。客户端安装完成后自动提供 `minem` CLI；Skill 由仓库或兼容 AI 产品的 Skill 安装机制提供，使用前必须确保当前 AI 产品可以读取对应 Skill。
13. 复制模板只包含动作、固定 Skill、2–3 个空白信息项、一个关键约束和结果要求；不得重复内嵌 CLI 绝对路径、诊断命令、能力清单和完整业务协议。分类、版本、幂等与验收细节由固定 Skill 统一维护。

### CLI 启用门槛

1. 客户端每次启动自动维护 `~/.local/bin/minem` 用户入口；每次打开创作助手都检查该入口或兼容系统入口是否存在且可执行。
2. CLI 不可用时先显示阻断式修复面板，隐藏全部场景，不允许复制无法执行的指令。
3. 修复面板必须保留收起与关闭入口；修复失败后停留在当前面板，可再次修复、收起或关闭抽屉，不请求管理员授权。
4. 安装成功后立即复检，无需重启客户端即可进入场景指令区。
5. CLI 复检只用于决定场景区是否可用；复制模板统一写 `minem`，不暴露本机绝对路径。外部 AI 通过安装后的 Skill 与 CLI 环境执行。

### macOS 适配

1. 抽屉使用 macOS 原生窗口定位和焦点行为，支持 Retina 与非 Retina 屏幕，不通过网页缩放模拟窗口尺寸。
2. 首次创建窗口时根据当前可用屏幕工作区贴右定位；用户拖动后，展开与收起保持当前窗口右边缘和垂直中心锚点，并限制在工作区内。外接显示器断开后，下一次尺寸切换自动夹紧到当前可用屏幕。
3. 展开态宽度为 `340` 点，高度在 `480–520` 点之间按当前工作区自适应；低于最小高度时只使用实际可用高度。收起窗口固定为 `48×48` 点，内部图标必须是完整圆形。右侧和上下安全边距不得小于 `12` 点。
4. 关闭、收起按钮在不同缩放比例下均保持至少 `32×32` 点的可点击区域；不显示 Windows 风格标题栏或重复的系统关闭控件。

### 汇报场景

| 场景 | AI 在对话中补充 | 固定技能与约束 |
| --- | --- | --- |
| 导入汇报 | 外部文件、文件夹或链接 | `minem-report-workflow`；多页生成一个汇报，每页生成一个页面素材，重复导入幂等 |
| 新建汇报 | 主题、受众、页面引用和顺序 | `minem-report-workflow`；复用已有页面，缺页时调用页面技能 |
| 插入页面 | 汇报、页面引用、插入位置 | `minem-report-workflow`；只新增汇报槽位 |
| 替换页面 | 汇报、目标页、替换来源 | `minem-report-workflow`；保留被替换页面 |
| 修改页面 | 汇报、目标页、修改要求 | `minem-report-workflow`；先生成页面新版本，再只替换当前汇报引用 |

### 页面模式

| 场景 | AI 在对话中补充 | 固定技能与约束 |
| --- | --- | --- |
| 导入页面 | 外部单页文件或链接 | `minem-html-page`；只生成一个页面素材，检测到多页时转汇报或案例 |
| 新建页面 | 主题、受众、内容和素材 | `minem-html-page`；默认 1920×1080 单页，无内置工具栏 |
| 复制页面 | 来源页面和变化要求 | `minem-html-page`；创建独立新版本 |
| 修改页面 | 来源页面和修改要求 | `minem-html-page`；保留旧版本及全部既有引用 |

### 案例模式

| 场景 | AI 在对话中补充 | 固定技能与约束 |
| --- | --- | --- |
| 提炼案例 | 外部文档、受众、案例重点 | `minem-case-material`；案例组不是汇报，每张案例页是独立页面素材 |
| 插入汇报 | 案例页、目标汇报、位置和顺序 | `minem-case-material`；只修改汇报编排，不删除案例页 |

### 指令框架

1. `quick-actions-core.mjs` 是唯一场景注册表，集中维护模式、标题、图标、短说明、固定技能、空白信息项和一句关键约束。
2. UI 只根据注册表渲染列表，不为场景复制表单、校验或事件代码；新增场景必须先补核心定义和测试。
3. 复制模板在每个信息项冒号后保留空白，用户可直接粘贴路径、链接、编号或要求；AI 只追问仍缺少的关键信息。
4. 每个模板只展示本场景最关键的一条分类或版本约束；完整规则只在对应 Skill 中维护，避免两套协议漂移。
5. 浮窗不读取、上传或保存剪贴板历史；只允许立即回读本次由 MineM 写入的文本以校验复制结果。浮窗不调用 MineM 写接口，写操作由用户选择的 AI 通过公开 CLI 执行。

### 验收标准

1. 抽屉可在主客户端之外快速唤起、收起、关闭和再次唤起，不影响客户端服务、导入任务或预览加载。
2. 汇报、页面和案例三组核心场景均可复制不超过 360 字符的可填写短模板；界面不存在任何输入控件或通用素材治理模式。
3. 用户无需在浮窗提供上下文；复制到 AI 输入框后，可在空白项直接粘贴汇报编号、页面链接、附件路径和要求。
4. 原生剪贴板或 WebView 剪贴板完成写入后，必须通过系统剪贴板完整内容校验才视为复制成功；复制内容可在外部 AI 对话中完整粘贴，且当前行、底部状态和 Toast 不相互矛盾。
4. 固定技能必须遵守页面单页、多页分类、版本不覆盖和非破坏性编排规则；短模板不得复制完整协议。
5. 指令可粘贴到 Codex 或同类 AI 产品，并明确调用已安装客户端中的固定 Skill 与 `minem` CLI。
6. 助手不执行导入、删除、编排确认等写操作，不引入重复导入、数据污染或服务并发问题。
7. 第一次成功启动可看到助手；关闭后可使用 `Option + Command + M` 或备用键 `Control + Option + M` 在 300 毫秒内再次唤醒。
8. 安装后的 Dock、Finder、应用切换器和菜单栏均显示 MineM 品牌图标，不出现通用占位图标。
9. 收起后仅显示右侧 `48×48` MineM 图标，点击图标在 300 毫秒内恢复抽屉；关闭图标和 `Esc` 在 300 毫秒内完全隐藏，快捷键可再次展开。
10. 主窗口关闭到托盘或最小化后，再次点击 macOS Dock 中正在运行的 MineM 图标必须恢复并聚焦原窗口，不创建重复窗口，也不重新启动本机服务。
10. CLI 用户入口缺失或不可执行时只显示修复面板；修复成功后操作区自动解锁。
