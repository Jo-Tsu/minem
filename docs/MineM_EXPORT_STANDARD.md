# MineM HTML 文档交付标准

版本：v1 · 2026-11-17。产品定位：个人 HTML 管理与快速创作。**稳定、完整、可独立打开的交付物优先于代码减量和包体减量。**

本标准参考“豆包工作产品对比”交付包的组织方式，先统一交付结构、画布约定与稳定性验收。已有页面的内容、品牌和排版保持保真；新生成页面可采用本标准的原生 HTML 页面结构。

## 参考文件的实际情况

参考包使用根目录 `index.html`，包含 20 个原生 HTML 页面，页面结构为 `.deck > .slide-frame > .slide`，默认画布为 1920×1080。配套资源包括 `assets/feishu-deck.css`、`assets/feishu-deck.js`、附加布局与编辑模式文件、输入素材和互动原型。

这份下载包属于带线上运行环境引用的版本，不能直接作为完整离线模板：本地依赖检查发现 136 条缺失引用；`assets-manifest.yaml` 列出 85 个文件，其中实际存在 7 个。主要缺少线上存储中的图片、视频等资源。其资源清单和开发文件不能原样视为合格成品。

## 默认交付格式

**主交付物为 HTML ZIP，PDF 作为静态阅读副本。** ZIP 使用汇报名称，解压后能直接找到根目录 `index.html`。默认打开方式是用浏览器打开该文件，基本播放不要求启动 MineM、安装依赖或登录原平台。

```text
汇报名称.zip
├── index.html
├── assets/                     # 播放框架和实际依赖资源
├── pages/                      # 混编多来源页面时使用
├── prototypes/                 # 实际使用的互动原型，可选
├── input/                      # 来源页面实际引用的输入素材，可选
├── assets-manifest.yaml         # 按实际导出文件重新生成
├── minem-export-manifest.json   # 标题、画布、页序和来源等元数据
└── README.md                    # 打开、播放、目录与适用环境说明
```

既有页面依赖可以保留其相对目录，包括每页自己的资源子目录。目录统一不得破坏相对路径或强行合并同名资源。所有实际路径以导出清单为准。

`.gitignore`、`.spark`、开发用 `package.json`、构建缓存、平台任务日志和未引用的原始上传包不作为默认交付内容。平台 AI 演讲台、TTS 模型和生成旁路文件不进入成品；原页面依赖的音频和视频音轨仍属于内容资源，应保留。

## HTML 与播放约定

- 文档采用 UTF-8，保留原有语言、文字、SVG 和 HTML 内容，支持等比适配与全屏。
- 新生成汇报默认使用 1920×1080、16:9 画布。已有其他尺寸页面保持原比例，适配时不裁切正文。
- 同一原生 Deck 来源可以保留一个多页 HTML 入口与原有播放框架。混编不同来源时可以保留独立页面，由根入口编排播放，避免样式和脚本全局变量冲突。
- 每页有可识别的标题和稳定页面标识；页数与已确认的可见页面数一致。
- 页面顺序、隐藏与移出状态使用已确认编排。任务开始后记录的页序及素材版本应保持一致，未确认的界面编辑不进入成品。
- 翻页按钮、键盘翻页、页码跳转和全屏可用；进入慢加载页面时有明确反馈，完成后自动撤掉提示。
- 基本播放支持直接打开本地文件。生成文件不能依赖对本地 JSON 的 `fetch`、需要开发服务器的模块加载或平台 API；必要数据可内联，脚本应按浏览器可直接运行的形式交付。
- 混编页面应专门验证本地文件模式下的键盘传递、媒体暂停和加载完成状态，不能只验证 HTTP 预览。
- 原页面的只读或编辑行为属于来源内容约定，不默认启用额外编辑功能。新增生成页面的交互应在交付清单和说明中可识别。

本标准统一交付规范，不要求将所有历史页面改成同一品牌、配色或对比布局。

## 资源与清单约定

必需图片、视频、GIF、SVG、音频、字体、CSS、JS 和互动原型随包交付。播放依赖使用有效的相对路径，不能遗留需要 MineM 服务、原平台会话或线上存储才能读取的地址。跳转到官方网站等普通外链可以保留，但不能成为基本播放的前提。

媒体文件按原始字节复制，保留原音轨、动效及清晰度。ZIP 压缩用于无损打包；不因减小文件体积而截图替代页面、转码视频或有损重压图片。仅为使资源路径可用而改写引用，不改变页面业务逻辑和事件行为。

`assets-manifest.yaml` 由实际复制的文件生成，不沿用旧清单。沿用参考包的 `framework`、`deck-local` 分类；`shared` 可以为空，不要求建立共享资源池。清单中的每个路径都必须存在。

扩展现有 `minem-export-manifest.json`，保持已有字段含义，至少记录：

- 格式与标准版本、根入口、汇报名称和编号。
- 汇报画布与可见页数。
- 每页的顺序、标题、来源编号和实际可打开的相对路径或原生页锚点。
- 实际资源路径及内容哈希，供完整性验证。
- 导出时间和内容保真策略。

原生页锚点必须由实际运行时确定，不能猜测。资源清单与页清单不额外生成相互矛盾的第二套定义。

## PDF 约定

PDF 使用与 HTML 相同的已确认页序和页数，作为静态阅读副本。每页渲染完成、字体与图片就绪后输出，页面清晰、内容完整，避免黑屏、占位态或动效中间态。任一页失败时整份导出失败并指出页号和原因。

PDF 不承诺保留音视频播放和网页交互；对应内容的完整交付使用 HTML ZIP。

## 稳定性验收

| 检查 | 通过条件 |
| --- | --- |
| 干净目录打开 | 解压到包含中文和空格的新目录，直接打开 `index.html`，无需安装依赖 |
| 独立播放 | 在隔离浏览器中断网，并停止生成该文档的隔离服务后，基本内容与翻页仍可用 |
| 页面完整 | 检查全部页面；页数、顺序和可见状态与任务记录一致，首、中、末页均正常 |
| 资源完整 | 必需资源均存在；图片、字体、视频和互动原型实际加载，不能只检查链接返回成功 |
| 清单一致 | 清单路径与实际文件一致，媒体哈希一致，ZIP 完整性校验通过 |
| 播放交互 | 按钮、键盘、跳页、全屏和慢加载反馈可用；隐藏页没有持续播放的声音或视频 |
| 再次导入 | 能识别为完整汇报并恢复页序和资源关系，重复导入同一包不会生成重复页面 |
| 失败反馈 | 缺资源或渲染失败时显示具体页与原因，不以“导出成功”交付残缺文件 |

README 必须有实际内容，说明打开入口、推荐浏览器、播放操作、目录用途和已验证环境。导出文件名应支持中文，下载响应需要正确编码文件名。

## 实现进展与剩余差距

2026-11-18 产品走查已经落实以下改进，并在实际候选镜像中验证成品：

- 混编包再导入读取 `minem-export-manifest.json`，按明确页清单恢复完整汇报、页序和标题；三页交付包恢复为一份汇报与三页素材，不额外把播放入口当成页面。
- 本地文件播放支持点击页面后的键盘翻页；切页时移除上一页文档，停止不可访问的隐藏页媒体。HTTP 播放继续使用相邻页缓存。
- HTML ZIP 成功前检查资源依赖闭合。缺失资源、未完成的完整性检查、必要联网依赖及页面资源清单中的联网媒体均导致导出失败，并返回具体原因。
- 隔离成品验证覆盖中文和空格目录、断网播放、音频暂停、ZIP 完整性和重新导入；PDF 样例验证页数、文件格式并逐页检查实际渲染。

### 2026-11-18 补充验收

- HTML ZIP 与单页 ZIP 已按实际文件生成资源清单、SHA-256 和 README。下载使用中文标题，并提供 UTF-8 Content-Disposition 与 ASCII 回退名。
- 单页导出改为收集依赖图，验证根目录 CSS、CSS `@import`、SVG 内嵌资源，以及超过 4 MB HTML 后部的引用。缺失必需资源会阻止导出。
- PDF 使用本机 Chromium 的管道接口等待实际字体、图片解码、有限入场动效及视频首帧；资源或脚本错误会使整份任务失败，并返回具体页号。没有增加运行库依赖。
- 39 页历史原生汇报完成本地资源补齐、逐页断网打开和媒体解码检查；文字与已有媒体字节保持一致。完整 ZIP 校验及清单哈希通过，重新导入恢复为一份汇报与 39 页素材。封面和正文两页 PDF 已逐页渲染复核。
- 多来源成品继续保留 `sources/`、`pages/` 与每页专属资源树；它们是被支持的实际布局，不能为了目录一致而破坏相对路径。

尚未覆盖所有来源的业务按钮、全部互动原型和 Safari/Edge 的完整组合。依赖第三方平台登录或运行接口的页面不能自动成为离线成品；必要联网依赖仍会阻止离线导出。不能把上述样例验收扩展为任意 HTML 都已通过所有浏览器验收。

每次落实一个完整交付改进并验证对应成品，保持现有素材和已确认编排可用，不进行无关代码减量。
